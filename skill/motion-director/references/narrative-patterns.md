# 六种叙事结构与同源情境

演示使用连续场景的叙事节拍，不强制一拍一切。可独立打开 HTML，用 seek(t) 定位。当前是 browser-demo，实际生产应按内容展开 Shot Plan。

## 主张 → 场景 → 证据

- ID：`combo.title-product-focus`
- 演示：`snippets/narrative-claim.html`
- 目标：从一句主张进入产品情境，再让可见证据回答它。
- 主体：任务窗口与唯一重点
- 条件：主张不是装饰标题，结尾必须能指出具体证据。
- 分工：导演选择明确的主张和证据对象；技术侧决定如何揭示、描线与取景。

- 0–2s：主张建立；观众知道要验证什么
- 2–6.4s：使用情境；看到主张对应的任务场景
- 6.4–9.6s：证据落定；能指出唯一重点如何支持主张

## 行动 → 响应 → 结果

- ID：`combo.capsule-input-result`
- 演示：`snippets/narrative-action.html`
- 目标：用角色的一次主动操作，建立系统响应与结果的因果。
- 主体：光标作为主动者、文档作为成果
- 条件：结果必须接住前面的输入，不能只是换一个成功提示。
- 分工：光标的路径服务于因果；打字、加载与提示的实现归完整词典。

- 0–3s：主动操作；看到角色做了什么
- 3–5s：系统回应；明白系统正在处理什么
- 5–9s：成果出现；知道得到的成果是什么

## 建立 → 聚焦 → 回归

- ID：`combo.phone-focus-return`
- 演示：`snippets/narrative-context.html`
- 目标：从全局找到重点，进入细节，再回到带有变化的全局。
- 主体：同一项目板中的目标区域
- 条件：回归时保留定位线索，观众知道细节属于哪里。
- 分工：本演示使用二维取景，不把 scale 叫真实摄影机推进。

- 0–2.2s：建立地图；知道全局有哪些区域
- 2.2–6.2s：进入重点；看懂重点区域的内容
- 6.2–10s：回归全局；知道该变化在全局中的位置

## 旧态 → 变化 → 新态

- ID：`combo.card-relay`
- 演示：`snippets/narrative-state.html`
- 目标：让同一组主体经历整理与连接，使观众看见变化过程。
- 主体：三个信息片段作为持续主体
- 条件：保留主体身份，不能用新卡淡入掩盖过程。
- 分工：位移和排序是实现；导演决定主体如何从散乱成为有序关系。

- 0–2.2s：旧态建立；看出旧态的混乱或限制
- 2.2–5.8s：变化发生；理解哪些主体被重新组织
- 5.8–10s：新态成立；看出新态为什么更清楚

## 对照 → 归因 → 确认

- ID：`combo.before-after-confirm`
- 演示：`snippets/narrative-compare.html`
- 目标：先展示同一任务的两种路径，再解释差异，最后确认改善。
- 主体：同一流程的两种版本
- 条件：条件与尺度一致，除了结果，还要说明差异来自哪里。
- 分工：流程为概念例；比较与归因属于导演，滑杆与图表实现属于技术。

- 0–3.2s：同条件对照；看到同一任务的两种路径
- 3.2–6.8s：追踪差异；知道哪两步被移除或合并
- 6.8–11s：改善确认；知道新路径为何更短

## 总览 → 选择 → 详情

- ID：`combo.overview-select-detail`
- 演示：`snippets/narrative-selection.html`
- 目标：用明确的选择动作，将一个群组中的主体交给详情镜头。
- 主体：三个方案与被选中的方案
- 条件：未选对象退出时保留选择关系，详情不能像无关的新页。
- 分工：主体身份、动作动机和注意力交接由导演规划；容器展开由技术实现。

- 0–2.2s：总览建立；看到可选择的整体
- 2.2–4.2s：选择发生；知道选中了谁
- 4.2–10s：主体接管；详情仍能认作原来的对象
