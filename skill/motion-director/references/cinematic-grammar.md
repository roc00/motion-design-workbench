# 电影语法：让镜头“会说话”（镜头组合高级层）

> 基础元素告诉你“单个动效怎么做”；本文告诉你“镜头怎么组合成一段电影”。
> 按内容分别说明主体、视点、状态交接与阅读时间。以下是可选词汇，不是每片必须满足的技法清单。

## 1. 景别（Framing）

| 名称 | English | 主体占比 | 表达 | 典型时长 | 常搭配 |
|---|---|---|---|---|---|
| 大远景 | Extreme wide | 人物/主体占画面高度 < 25% | 世界、环境、渺小、宏大 | 1.2–2s | gradient-field, grid, horizon |
  - ⚠ 大远景里别放需要读的小字，看不清
| 全景 | Wide | 主体完整可见，占 25–50% | 建立场景、全局体系、舞台 | 1–1.8s | board-flyover, parallax, grid |
  - ⚠ 全景是建立镜头，停留别久，交代完即推近
| 中远景 | Medium long | 主体占 50–70% | 在环境中行动、上下文 | 0.9–1.6s | tracking, parallax |
  - ⚠ 中远景最容易『什么都想说、什么都不突出』，要有一个焦点
| 中景 | Medium | 主体占 60–90% | 功能主体、交互、日常操作 | 1.2–2.4s | cursor, type, push-in |
  - ⚠ 默认全用中景会变成 PPT；要和特写/大字交替
| 中近景 | Medium close-up | 主体占 90–120%，局部关键 | 聚焦一件事、一个动作 | 1–2s | cursor, macro-ui, match-cut |
  - ⚠ 主体放大后注意文字别断行、溢出
| 特写 | Close-up | 单个控件/元素占满画面 | 重点、证据、情绪 | 1–1.8s | macro-ui, living-number, chart-draw |
  - ⚠ 特写是给观众『确认』的，落定后要有一拍停顿
| 大特写 | Extreme close-up | 控件局部放大 3–4 倍 | 质感、关键细节、强度 | 0.8–1.4s | depth-of-field, macro-ui |
  - ⚠ 大特写要配景深虚化其余，避免画面杂乱
| 微距文字 | Macro type | 单个词/数字占画面 40–70% | 钩子、章节、数字证据 | 1–1.6s | kinetic-slice, living-number, whip |
  - ⚠ 微距词必须有意义（痛点、结论、数字），别用 NEW/UPDATE 这类空词

## 2. 运镜（Camera Moves）

| 名称 | English | 表达 | 动机 / 参数 | 坑 |
|---|---|---|---|---|
| 推近 | Dolly / push in | 聚焦、强调、进入、张力上升 | 推向即将发生动作的那一个元素; amount: 真实相机前移改变透视；若以 2D scale 放大，标为 virtual-reframe; ms: [700, 1600]; ease: spring(140,20) / ease-out | 全程匀速推（linear）会很死；用 ease-out，落定停一拍 |
| 拉远 | Pull / dolly out | 揭示全局、收尾、释然、体系 | 让观众看到『原来它属于这么大的系统』; amount: zoom 1.2 → 1.0; ms: [900, 1800]; ease: spring(120,18) | 拉远时背景元素要提前布好，否则拉到一半没东西可看 |
| 摇 | Pan | 环视、并列、从 A 扫到 B | 视线随一个移动元素或因果方向移动; amount: 真实摄影机绕固定位置改变观察方向；x 平移另标二维取景或 truck; ms: [600, 1400]; ease: ease-in-out | 摇的方向要遵循 180° 轴线；大幅摇配轻微模糊更顺 |
| 移 / 跟拍 | Tracking / truck | 陪伴、推进、一镜到底、穿越 | 跟随光标/主体在产品里走，最有『电影感』; amount: x/y 连续平移，前景后景速度差; ms: [1500, 4000]; ease: 连续 + 多层视差 | 区分主体横移、二维取景和摄影机平移；需要空间感时才使用视差，并说明各层深度。 |
| 环绕 | Arc / orbit | 很多东西连接到一个核心、生态 | 产品有很多集成/服务商/插件时; amount: 摄影机/观察视点绕主体改变，按真实透视投影与深度排序；椭圆上主体移动另标 subject-orbit; ms: [1500, 3000]; ease: 连续慢转 | 别为凑满一圈虚构成员；数量=真实集成数 |
| 升降 | Crane / boom | 登场、升华、俯瞰 | 从低处抬起到俯瞰全局，或反之; amount: 真实视点高度改变；y 与 scale 模拟另标 2D approximation; ms: [1000, 2000]; ease: ease-in-out | 升降要配合地面/网格层，否则没有高度参照 |
| 甩 | Whip pan | 时间跳跃、快节奏、转场遮蔽 | 用运动模糊遮住切点，实现两个并列表里的快切; amount: 快速大幅横移 + 方向模糊 100–200ms; ms: [180, 350]; ease: ease-in-out | 甩出和甩入要在同方向、同速度，否则接缝断 |
| 视差移焦 | Parallax rack | 纵深、空间、高级 | 内容需要表达前后关系时，利用深度和焦点变化；不要给每个镜头添加视差; amount: 前景 1.6× / 中景 1.0× / 背景 0.5× 速度; ms: [800, 2000]; ease: 三层各自 ease | 三层内容别互相遮挡焦点；中景主体始终最清晰 |
| 手持 | Handheld | 真实、临场、纪录片感 | 需要真实录屏/纪实气质时偶尔用; amount: x/y 高频小抖动 + 轻微旋转; ms: 贯穿; ease: 噪声叠加（固定种子） | 产品 UI 片慎用，抖太久显廉价；幅度要小 |
| 固定机位 | Static | 安静、克制、庄重 | 让注意力集中在排版、操作、状态变化或阅读; amount: 固定视点；没有叙事需要时不添加呼吸漂移; ms: —; ease: — | 留出必要阅读停留；检查是否存在没有内容作用的停顿，而不是强制运镜。 |

## 3. 纵深（Depth）

需要表达空间关系时，可使用下面的层级；二维排版不必强加三层：

| 层 | 作用 | 视差速度 | 虚/实 | 透明度 | 例子 |
|---|---|---|---|---|---|
| 前景 | 框景、掠过、增加纵深 | 1.4–2.0×（相机移动时最快） | 可轻微虚化 | 0.5–0.9 | 虚化的光斑/色块掠过, 半透明 UI 边缘, 颗粒/尘埃 |
| 中景 | 主体所在，始终最清晰 | 1.0× | 0 | 1 | 产品卡片, 正在操作的控件, 数据主体 |
| 背景 | 世界、环境、氛围 | 0.4–0.7×（最慢） | 慢层可虚化 | 0.6–1 | 世界场（粒子/流线/字符）, 网格/地平线, 大色团 |

假纵深（fakeZ）的 5 种做法：

- scale：越近越大（主体 0.8→1.2）
- translateY：越近越靠下、移动越快
- blur：不在焦点的层虚化（2–8px）
- alpha/明度：越远越暗、对比越低
- shadow：沿 Z 抬起的元素加阴影、背景压暗

纵深规则：
- 需要空间关系时才分前、中、后景；二维编辑排版可以不使用纵深层。
- 真实视点变化产生投影和遮挡变化；二维速度差是视差近似，需要如实标注。
- 主角在当前节拍中保持清楚，不让装饰抢走阅读。
- 渲染层根据内容选择，避免为层数增加 GPU 或维护成本。

## 4. 构图与走位（Blocking）

锚点网格（3×3）——别总居中：

| 位置 | 名称 | 坐标(x,y) |
|---|---|---|
| lt | 左上 | 0.33, 0.28 |
| ct | 上中 | 0.5, 0.28 |
| rt | 右上 | 0.67, 0.28 |
| lm | 左中 | 0.33, 0.5 |
| cm | 正中 | 0.5, 0.5 |
| rm | 右中 | 0.67, 0.5 |
| lb | 左下 | 0.33, 0.72 |
| cb | 下中 | 0.5, 0.72 |
| rb | 右下 | 0.67, 0.72 |

构图规则：
- 主体默认放在三分线交点（0.33/0.67），而不是死正中；正中只留给 logo、章节大字、最终 lockup
- 主体朝画面内移动时，在朝向的一侧留『引导空间』（leading room）；人/光标前方留空
- 大标题/主体上方留约 1/3 头空（head room），别顶到上边缘
- 用『负空间』突出主体：主体周围留白，不要让元素铺满整个画面
- 视线引导：让线条、光、光标、元素排列指向你要观众看的下一个焦点
- 9:16 竖屏重要内容避开底部约 13%（UI 安全区）

四种构图模式：
- **asymmetric 非对称三分**（功能镜头、叙事、钩子）：主体在三分点，另一侧用小元素/留白平衡
- **centered 居中对称**（logo、章节、片尾 lockup）：居中只在仪式感时刻，全片不超过 2–3 次
- **split 分屏/双栏**（前后对比、并列）：同构布局、相同尺度，分界移动
- **diagonal 对角线**（飞越、推进、能量）：元素沿对角线排布，制造动感

## 5. 世界（Worlds / 背景舞台）

| 名称 | 表达 | 从产品推导 | 搭建 | 坑 |
|---|---|---|---|---|
| 粒子场 | 分散→汇聚、宇宙、能量 | 点阵 logo、数据点、用户/节点 | 粒子有初始位置+速度，靠噪声漂移；汇聚时从渲染好的 SVG 取格子 targets，落定后换清晰 SVG | 通用粒子爆发是 slop；粒子必须有『去的目标』 |
| 流线场 | 速度、进入一个世界、流动 | 产品的『快/多/流式』 | 线段位置 = 速度的积分，沿一个方向流动，速度有快慢层次 | 安静/写作类产品用它显浮夸 |
| 字符/数据场 | 代码、数据、底层、智能 | 产品自己的代码、数据、文本 | 2D 字符网格 + 噪声控制亮度，中心留空放主体 | 面向非技术受众显得冷；字符要与产品相关 |
| 渐变场 | 情绪、品牌色、氛围 | 品牌色丰富 | 慢速移动的大色团，低对比，不抢主体 | 别铺在密集界面后面，看不清；纯渐变背景+居中字=slop |
| 网格/点阵 | 秩序、工具感、科技 | 设计/数据工具、布局 | 极淡的点/线，随相机有视差，不要太亮 | 别和界面自身的网格打架 |
| 发光地平线 | 登场、仪式感、发布 | 暗色、高端产品 | 多层径向渐变 + 暗色本体遮挡，光从地平线升起 | 不要连续镜头都用；浅色产品不适用 |
| 纸与墨 | 书写、温度、内容 | 写作、笔记、内容产品 | 纸纹理 + 墨迹扩散遮罩，文字逐笔写出 | 纹理太重显脏；保持干净 |
| 光斑/漏光 | 质感、氛围、梦幻 | 需要情绪/品牌温度 | 虚化光斑缓慢漂移，少量前景掠过 | 光斑太多会糊成一片，焦点要清晰 |
| 纯色/留白 | 克制、极简、编辑感 | 极简 UI、内容为王 | 干净底色 + 少量元素，靠排版与内容运动 | 留白时必须有事件（打字/移动），否则空 |

## 6. 转场（Transitions）

| 名称 | 何时用 | 搭建 | 坑 |
|---|---|---|---|
| 硬切卡拍 | 冲击、明暗突变、列表推进 | 切点落在拍点上；前一镜先把主角模糊/移出，切得更干净 | 浅色和深色镜头之间不要做长交叉淡化，中间会发灰，用硬切 |
| 匹配剪辑 | 前一镜的元素就是下一镜的主角 | 前一镜某元素放大/运动，下一镜从同一位置、同一大小、同一形状接续，画面无缝 | 两镜的匹配元素形状、颜色、运动方向要一致 |
| 穿越缩放 | 从概念进入产品内部 | 前一镜主角放大并淡出/模糊，后一镜从略大缩回，像穿过它 | 穿出的落点要提前在时间轴上测出（screenCenterAt） |
| 甩镜转场 | 并列、快节奏、时间跳跃 | 同方向甩出（模糊）→ 甩入，中间 100–200ms | 首尾方向速度必须一致 |
| 白闪/黑场 | 大段落之间、重大揭示 | 0.15–0.25s 全白/全黑 + 冲击音 | 频繁用会廉价；整片 1–2 次 |
| 遮罩擦除 | 并列功能、前后对比 | 用一个来自产品的形状（圆角矩形、logo 形状）擦过，露出下一镜 | 遮罩形状要来自产品语言，别用无关图形 |
| 形状变形 | 一个元素变成另一个（同点数） | SVG path 插值（点数一致）或遮罩，中间态保持饱满 | 点数不一致会扭曲；变形中间态最容易丑 |
| 交叉淡化 | 仅明/暗相近的同类镜头 | 短，150–300ms，且两镜头亮度接近 | 深浅镜头之间禁用（发灰）；全片靠淡化=slop |

## 7. 连续性 / 匹配剪辑（Continuity）

连续性规则：
- 180° 轴线：相邻镜头里，主体/运动方向保持在同一侧，不要左右颠倒
- 匹配元素：跨镜头的同一元素保持形状、颜色、标识，主体身份不能在切点丢失
- 视线/运动接续：前一镜的运动方向指向下一镜的起点，形成『接力』
- 亮度连续：相邻镜头底色亮度别突变（要么同类硬切，要么先模糊再切）
- 首尾呼应：循环片的最后一帧等于第一帧（光标位置/速度也包含）
- 一镜内元素靠相机/变形连接，不靠整屏淡入淡出

接缝技法（seam techniques）：
- 用相机运动把切点遮住（推近/甩/穿越时切）
- 用一个『贯穿元素』（光标、一条线、一个形状）连续穿过两镜
- 前一镜先模糊主角，硬切到下一镜清晰主角

## 8. 从产品推导运镜（Derived Moves）——“因为产品有 X，所以用 Y”

> 每个手法都必须能写成『因为产品有 X，所以用 Y』。这是反千篇一律的核心：同流程给不同产品，画面必须不同。

| 产品有 | 因此 |
|---|---|
| 点阵构成的 logo | 粒子从远处汇聚，落进 logo 点阵的每一格，落定后换清晰 logo |
| 接入很多服务/服务商/插件 | 成员沿一个倾斜的环绕着核心界面转，纵深控制大小 |
| 以代码/数据为材料、面向开发者 | 用产品自己的代码/数据组成字符场，中心留空 |
| 写作/笔记/内容 | 字逐笔写出，纸张纹理，墨迹晕开 |
| 数据分析/可证明的数字 | 真实图表路径逐段画出，数字滚动落定 |
| 设计/排版工具 | 构造线、控制点、网格吸附，元素被『设计』出来 |
| 多人协作 | 多个光标同时进入，状态实时合并，队友光标带路 |
| Agent/对话/生成 | 真实打字 + 流式回复按时间截断，逐字出现而非整段 |
| 很多卡片/模块的页面 | 平放看板从 50–60° 抬到 10–20°，镜头飞越 |
| 明确的痛点被解决 | 槽位轮换（痛点重复、间隔加快）→ 产品出现一镜擦除 |
| 性能/版本改版 | 同构前后对比，分界移动，标记真实差异 |
| 层级/列表导航 | 总览选中项明确，推近接续进入详情，身份保留 |

## 9. 方向推导（Direction）——让手法是这个产品专属的

方法：沿不同轴提出 3 个方向，彼此至少在 3 个轴上不同，各自内部自洽，再按产品气质/受众/平台选一个并写理由。

方向轴（备选方向至少在 3 个轴上不同）：

- **base-light 底色与光**：黑色舞台+发光 / 纸白+墨线 / 品牌大色块 / 明暗交替 / 真实环境
- **type-sound 字体与声音**：超细大字 / 粗重冲击 / 衬线编辑感 / 等宽技术 / 圆润亲和
- **motif 母题来源**：logo 几何 / 界面本身 / 数据形态 / 领域隐喻 / 用户场景
- **camera 镜头语言**：平面排版 / 3D 舞台（倾斜/环绕/飞越）/ 微距特写 / 一镜到底 / 录屏质感
- **transition 转场词汇**：硬切卡拍 / 穿越缩放 / 遮罩擦除 / 形状变形 / 匹配剪辑
- **pacing 节奏**：发布会式从容 / 预告片式紧凑 / 轻快俏皮 / 安静叙事
- **sound 声音**：电子脉冲 / 钢琴与弦 / 打击乐主导 / 氛围铺底 / 用户曲目

叙事结构：
- 钩子→品牌→功能证明×3-5→小功能快切→收尾（适合 发布/通用）
- 问题→转折→解决（适合 解决明确痛点的更新）
- 完整做完一件真实任务（适合 Agent/工作流）
- 一镜到底穿过产品各区域（适合 空间感强的界面）
- 前后对比（适合 性能/改版）
- 倒数清单（适合 很多小更新）
- 一天的使用（适合 日常工具）

## 10. 镜头规范（Shot Spec）

- **frame**：9:16 用 1080×1920；16:9 用 1920×1080；安全区避开底部约 13%
- **fps**：60fps（至少 30），运动模糊用 4 子帧混合
- **typeScale**：
  - hero：90–190px，粗 700–900
  - section：56–90px，粗 700–800
  - body：界面正文成片 ≥22px（1080p），说明 28–42px
  - caption：36–48px
- **interfaceScale**：界面正文倍数 ≈ 22 ÷ 产品正文像素；完整窗口只做建立镜头
- **motionRange**：入场 300–700ms；功能证明 1000–2400ms；快切 180–500ms；读字停留 ≥1000ms
- **fonts**：一种展示字体 + 一种 UI 字体；中英文分别指定（英文衬线/无衬线 + 中文无衬线）
- **color**：一个主色 + 一个强调色，除非 brief 要求更多
- **doNot**：['不用回弹（bouncy）在数据/数值运动上', '不用彩虹色、UI chrome 发光、廉价光泽', '不用 will-change 在相机要缩放的元素上（文字发虚）', '弹出层/portal 在 3D 变换里定位会错，打开时回平面']

## 11. 电影序列反 Slop（区别于初学者作品）

> AI 烂片的可识别特征。不仅要『避免』，更要理解它为什么烂——它们让画面变成『静止的、居中的、彼此割裂的』。

| 禁止的模式 | 为什么差 | 替换为 |
|---|---|---|
| 居中标题压在渐变背景上 | 无构图、无纵深、是默认最偷懒的布局 | 主体放三分点，背景是有纵深的世界层 |
| 所有元素统一 fade in / fade out | 等于没有运动设计，全靠透明度过场 | 用相机推进/变形/遮罩/位移，元素从画外进入 |
| 四角标签、整帧边框 | 装饰性 HUD 抢主体，是放映机模板残留 | 除非刻意放映机风格，否则去掉，信息进画面 |
| UI chrome 上 glow / 发光 | 廉价、显脏 | 用层次/阴影/明暗，不发光 |
| 通用粒子爆发 | 粒子没有目标，纯装饰 | 粒子汇聚成具体目标（logo/数据） |
| 死帧（>2.5s 无任何事件） | 观众觉得拖沓 | 每 2–4s 有新事件，或机位/内容在动 |
| 缩放后文字发虚 | 在被缩放的层上用了会模糊的变换 | 文字用最终尺寸渲染，不在放大层上贴字 |
| 循环接缝卡顿 | 首尾帧不一致 | 最后一帧=第一帧（含光标/速度） |
| 一镜里所有元素同一种入场 | 单调、像模板 | 入场方式轮换，分前景/中景/背景错峰 |
| 同一种转场连用三次 | 重复、套路 | 转场词汇交替，深浅镜头硬切 |

## 12. 电影序列评分卡（目标每项 ≥ 8）

- **前 2 秒钩子** — 第一眼是否立刻有一个强画面/一个问题/一个数字，让人想继续看？
- **手机可读** — 360px 宽下所有字是否清晰、不重叠、不断行？正文 ≥22px？
- **运动质量** — 是否有弹簧/缓动（非 linear）、有相机运动、有纵深视差、无死帧？
- **纵深与构图** — 是否 ≥3 层、非居中、有视差、焦点最清晰、有负空间？
- **多样性** — 景别是否交替（全景↔特写↔大字）、入场/转场不雷同？
- **连续性** — 镜头之间是否有匹配/接力、方向一致、接缝无缝、循环对齐？
- **品牌与推导** — 手法是否都能从产品推导、用真实组件/配色、一眼像这个产品？
- **声画同步** — 音乐/音效是否卡拍、关键反馈听得见、音乐让位？

## 13. 首帧规则

首帧必须是完整画面：平台无封面时会抓第一帧当缩略图。前 5–10 帧放一个开场段落的完成态，之后再淡出、开场动画照常。第一帧不能是空白底色，也不能是等待入场的背景。

检查方法：渲染后检查前 5 帧是否为完整画面
