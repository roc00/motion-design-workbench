# 00 · 体系总览

面向 Agent 制片（AI 做动效视频）的选型参考。把「怎么描述一个动效」和「这个镜头该用什么」拆成两条正交的轴。

- **描述轴（怎么把它说清楚）**：第一层技术工具 → 第二层触发方式 → 第三层动效类型 → 第四层 UX 规则。
- **选型轴（该不该用它）**：五个视频场景。
- **性质轴（它是什么）**：效果 / 原理 / 规则。原理与规则不是画面动作，不作场景主效果推荐。

---

## 一、三个轴

### 描述轴：四层结构

| 层级 | 回答的问题 | 举例 | 数据位置 |
|---|---|---|---|
| 第一层 · 技术工具 | 用什么实现 | CSS、Motion、GSAP、Three.js、Lottie、Rive | `data/tools.json` |
| 第二层 · 触发方式 | 什么时候开始 | Hover、Focus、Click、Pointer、In view、Scroll-linked、Gesture、Route、State、Timer | `data/triggers.json` |
| 第三层 · 动效类型 | 画面具体怎么动 | 按行显现、视差滚动、柱状对比、共享元素转场 | `data/effects.json`（`nature: effect`） |
| 第四层 · UX 规则 | 怎样动才好用 | Feedback、Affordance、Focus、Reduced motion、Input modality | `data/effects.json`（`nature: rule`） |

**必须分开的理由**：滚动是第二层（触发方式），视差滚动才是第三层（动效类型）；点击是第二层，「弹窗从触发按钮附近放大出现」才是第三层。混在一句话里，AI 只能自己挑，通常挑最花的那种。

最容易被混写的两处：

1. **进入视口 vs 跟随滚动**。前者像按播放键，触发后动画自己播完；后者像拖进度条，滚到哪播到哪。
2. **缓动 / 时长 / 延迟是原理不是效果**。它们是参数的取值方式，所有动效都在用，所以顶层单独标成 `nature: principle`。

### 选型轴：五个场景

| 场景 | id | 目标 | 硬约束 | 默认渲染层 |
|---|---|---|---|---|
| 文字展示 | `text` | 最短时间内读懂，并感到它重要 | 文字必须 100% 正确且高频改文案 | 确定性层 |
| 背景转场 | `bg` | 把两个镜头缝在一起 / 建立氛围 | 纯像素变换，不需要模型理解世界 | Shader 层 |
| 卡片展示 | `card` | 看懂有几张、什么关系、看哪一张 | 卡片内是真实文字与数字 | 确定性层 |
| 手机产品演示 | `screen` | 竖屏画框里可信地演示一次操作或展示产品 | 触屏没有悬停；内屏比例与输出画幅是两件事 | 确定性层 |
| 图表数据叙事 | `chart` | 3–8 秒看懂一个数据结论并能停在可读终态 | 数值必须精确可审计；图元不做超调插值 | 确定性层 |

### 性质轴

| 取值 | 含义 | 界面表现 |
|---|---|---|
| `effect` | 具体动效，可以直接作为场景主效果 | 正常参与首选 / 可用 / 慎用排序 |
| `principle` | 缓动 / 时长 / 延迟：参数的取值方式 | 保留演示，单列「原理与规则」，不作主效果推荐 |
| `rule` | UX 五条：约束所有动效 | 同上 |

### 场景适配度

每个动效在五个场景下都有适配度，这是选型表的原子数据：`core` 首选 / `good` 可用 / `caution` 慎用 / `avoid` 不用。

当前分布（`npm run validate` 自动统计）：

```
text    core 11 · good 13 · caution 10 · avoid 28
bg      core  8 · good 14 · caution  7 · avoid 33
card    core 16 · good 28 · caution 15 · avoid  3
screen  core 17 · good 24 · caution  9 · avoid 12
chart   core 11 · good 17 · caution 11 · avoid 23
```

**唯一真相源**：适配度只写在 `data/effects.json` 的 `scenarios` 字段里。`data/scenarios.json` 只记录描述与注意事项；界面、校验器和矩阵生成器都从场景注册表读场景，不写死数量。

## 二、三层数据

| 文件 | 管什么 | 谁在用 |
|---|---|---|
| `data/effects.json` | 条目本身：四层归类、nature、五场景适配度、参数区间、提示词、视频注记 | 界面 / 校验 / 矩阵 / 注册表导出 |
| `data/scenarios.json` | 场景定义、约束、节奏、注意事项、提示词模板 | 同上 |
| `data/presets.json` | **实际运行值**：每条演示的内容、时间安排（动作 / 交错 / 停留 / 退场）、代表帧、资产；手机三镜头；图表示例数据 | 预览 / 制作指令 / 镜头配置 |
| `data/triggers.json` · `data/tools.json` | 触发方式与工具、渲染层 | 同上 |
| `data/shot-recipes.json` | **44 张常用镜头卡**（28 张开源精选〔原 30，合并/退役 2〕+ 16 张视频拆解）：作用对象（摄影机/主体/画面衔接/时间节奏）、叙事用途（建立/引导/揭示/确认）、所属层、配方使用说明、三态接入状态、视频证据 `evidence[]`、覆盖标签 `tags[]`、合并变体 `aliases[]`、可复制制作描述（`shot.*`）与逐帧演示（`demoIndex` 含动作节点与分卡时长） | 镜头语言工作台 / 校验 / Skill 消费 |

**推荐范围属于词典，具体运行值属于预设**，两者不混写。构建时合并成 `public/registry.json`（带 `schemaVersion`），可直接读取，不新增服务端 API。

## 三、输出：同一份已解析配置，三种用途

`npm run build` 之前会跑一道绑定闸门：`effects.json` 的 `demo` + `demoVariant` 必须在 `src/engine/` 里解析得到，否则构建失败——防止「数据里写了 clip、代码里叫 clip-path-reveal」这类静默错配。

界面上的「当前配置」由 `默认值 ⊕ presets.json ⊕ 项目预设 ⊕ 用户在界面上的改动` 在 `src/runtime-config.js` 中解析一次，同一份结果同时驱动：

1. **预览**：卡片与详情复用同一个 renderer 与同一份 preset，只改变尺寸与控件。
2. **制作指令（中文）**：一条可直接交给做片子的人或 Agent 的话，含场景、画布、动作/交错/停留/退场的毫秒与帧数、handles、内容、结束状态、实现层与约束。
3. **镜头配置（JSON）**：结构化交付物，保留 ShotSpec 的字段形状。

配置里 **推荐渲染层** 与 **当前示例能力** 是分开的两个字段：写了 `deterministic` 只是推荐，示例能力明确标注为「浏览器内可定位演示」，不声称已完成 HyperFrames 或 Remotion 适配。

交错语义已经固定：`staggerMs` 是相邻元素开始时间间隔，`staggerSpanMs = staggerMs × (staggerCount - 1)`；可见时长为动作、整组交错、停留与退场之和。

## 四、默认制片参数

| 参数 | 默认值 | 原因 |
|---|---|---|
| 分辨率 | 1920×1080（另支持 1080×1920） | 覆盖主流生成模型最高官方输出，同时降低测试成本 |
| 帧率 | 24（可选 24/25/30/60） | 与主流生成模型同基准，减少 cadence conversion |
| 转场 handles | 前后各 12 帧 | **单列记录，不混进可见镜头时长** |
| 音频 master | 48 kHz | 内部统一规格 |
| Alpha | 按需输出 RGBA（ProRes 4444 / `yuva444p10le`） | 只在需要叠加时使用；生成层一律按不透明 plate 设计 |
| 设备内屏 | 393×852（中性设备框） | 内屏比例与输出画幅分开配置 |

另有独立项目预设 `opportunity-ai-vertical`：1080×1920、30fps、`portrait-stack`。它不会修改通用默认值。

## 五、演示可信度约定

为了让「预览」和「成片」对得上，演示内核遵守四条：

1. **画面由当前帧决定**：`render(t)` 是纯函数，任意顺序 seek 到同一帧结果一致。离散文案（逐字、变形）与随机效果（乱码、拖尾粒子）都由帧计算，固定种子，不依赖历史回调。
2. **统一控制器**：`ready / play / pause / seek / reset / destroy / capabilities`。暂停覆盖全部 GSAP 时轴，销毁幂等且清理资源。
3. **两种模式**：视频演示（预设时间轴，可任意定位）与交互原理（真实滚动 / 指针，只显示该模式支持的控件）。
4. **减少动态**给静态终态或短促淡化，而不是简单减速。

已知的素材限制：演示图片来自 Lorem Picsum（`picsum.photos`，固定种子）。**固定 seed 只保证每次拿到同一张图，不等于可复现资产**——生产请把这批图本地化后再进流水线。

生产组合使用更严格的资源门禁：等待字体、图片和视频全部成功；远程 URI 或加载失败会阻止播放。能力状态分为 `browser-demo`、`production-adapted`、`production-verified`，当前首批六个组件只到「已适配，待成片验证」。组合与 Shader 合同见 [05 · 生产适配与组合镜头](./05-生产适配与组合镜头.md)。
