## 一、总体分析：当前镜头系统缺什么、最该补什么

### 1.1 现状判断：现有 30 卡偏「UI 组件动效」，缺「镜头间电影化连接」

把现有 30 张卡按职责归类后可以看到一个明显的重心偏移：

- **UI 组件与入场（12 张）**：`ui-entrance.*` 6 张 + `interaction.*` 4 张 + `data.*` 4 张里的多数，回答的是"一个组件怎么出现、一次交互怎么反馈、一个图表怎么长出来"。
- **字卡与节奏（5 张）**：`typography.paper-title-card`、`rhythm.*` 3 张、`opening.*` 2 张里的节奏部分，回答的是"切在哪、切多快"。
- **镜头运动（4 张）**：`camera.*` 4 张 + `transition.*` 6 张。其中 transition 多为**单点技法**（wipe / card-flip / circle-iris / line-carry / hidden-cut / shot-seams），camera 多为**建立空间的通用推拉升降**。

也就是说，现有体系强在"**单镜头内部怎么动**"和"**组件怎么进场**"，但弱在"**两个镜头之间靠什么电影化地连起来**"——也就是导演/剪辑层面的"这一镜怎么接到下一镜"。

### 1.2 57 个样本暴露的真实缺口

跨片统计后，出现频次最高、且现有 30 卡**没有对应**的衔接能力集中在以下六类：

| 缺口能力 | 跨片出现情况 | 现有 30 卡为何没接住 |
|---|---|---|
| **穿过式运镜（zoom-through / 穿框穿越）** | 8+ 个视频：Win365、Blink、NotReal、CDX、ColCircle、阿里、快手、creatoroly、平安、蚂蚁 | 只有 `crash-zoom-punch`（快速强调），没有"穿过一个开口进入新空间"的镜头级连接 |
| **动势/形状/色彩匹配剪辑** | 几乎每个 showreel 都用 | 只有 `circle-match-iris`（圆形开合），没有通用形状/动势/整屏色幕匹配 |
| **共享元素跨镜连续形变** | Zelios、支小宝、Dia、Google AI、Microsoft 365 等 | 只有 `morph-from-primitive`（单次几何→UI），没有"同一元素跨多镜一路形变" |
| **光标/设备框/屏幕录制连续性** | Wayframe、panel4、Similarweb、Gemini、CDX、荣耀 | 只有 `input-trigger-moves`（单次触发→结果），没有"光标当主角/设备框不切换内容"的跨镜连续 |
| **辉光漏光藏切 / 光化开新场景** | panel2、Blink、Win365、xAI、AGIC、Framer、蚂蚁 | 只有 `transition-hidden-cut`（借亮度峰值藏切），没有"发光体本身化成后镜光源" |
| **后拉揭示 / 克隆成墙 / 分屏合分** | flowith、Stripe、MXD、快手、荣耀、Conduit | 没有"从一个特写顿悟全貌""一个克隆成矩阵""一分为二再合回"的结构节拍 |

### 1.3 最该补的能力（优先级）

1. **第一优先：穿框穿越（zoom-through-portal）**——它是 57 个样本里跨片证据最厚、最具"电影感"、也最容易用 DOM/SVG/GSAP 的 scale+径向模糊+遮罩参数化实现的能力，且直接对应 `combo.phone-focus-return`（全局→局部→回归）。
2. **第二优先：三类匹配剪辑（形状 / 动势 / 色幕）**——这是 showreel 的"通用粘接剂"，参数化只需"对齐形状位置 + 同色桥 + 运动方向连续"。
3. **第三优先：共享元素连续形变 + 设备框/光标连续性**——把"多 UI 不切黑串成一镜"工程化，是 AI 产品片最刚需的表达。
4. **补结构节拍：后拉揭示全貌、克隆成墙、分屏合分**——补齐"总览→选择→详情"叙事的前后段。

**核心结论**：现有体系是"组件动画词典"，缺的是"**镜头与镜头之间的剪辑句法**"。本报告据此抽出 16 张候选卡（见第三、八节与 `candidate-cards.json`），全部聚焦"电影化衔接"，而非堆砌数量。

- 高价值机制：① `18/37/45` 彩色漏光/色散光带章节藏切（light-leak-chapter-cut）；② `90–102` 高速运动模糊连续藏切多场景（speed-ramp-blur，与现有 speed-ramp-freeze 相邻）；③ `104–106` 粒子聚合成 AS（particles-gather-to-logo）。

## 三、Transition Pattern Library（跨片去重后的衔接语言）

> 下列 20 个 Pattern 按"证据厚度 + 可程序化程度"排序。每个给出：出现频率与证据视频（含时间戳）、机制（前镜留什么/后镜怎么接/为何自然）、动势方向与缓动、适用场景、可程序化程度。
> 标 ★ 者为已收入 `candidate-cards.json` 的 16 张候选卡；其余为库内观察项（证据尚薄或与现有卡过近，暂不立卡）。

### A. 镜头级穿越与进入

**P1 ★ Zoom-Through Portal（穿框穿越运镜）**
- 频率：极高，8+ 视频。证据：Win365 `0.0→5.2`；Blink `10.4→15.6`；NotReal `28.7→32.0`；CDX `6.4→11`；ColCircle `74.9→80`；平安 `128→134`；蚂蚁 `59→64`；creatoroly `10.4→14.3`。
- 机制：前镜把一个可穿过的开口（圆窗/门框/字卡隧道/UI 面板）放中轴；后镜从开口中心反方向推出。开口在穿入时放大到满屏、加径向模糊藏切。自然是因为"穿过"是人类对"进入新空间"的直觉。
- 动势/缓动：沿 Z 轴先加速后稳；`ease-in-out`，穿口瞬间 `ease-in` 拉满速度。
- 适用：章节跳入、界面↔现实往返、进入"数字深处"。
- 可程序化：高——SVG 遮罩+scale+径向模糊即可。

**P2 ★ UI Drill-In & Drill-Out（UI 钻进钻出）**
- 频率：高。证据：Wayframe `9.1→11.7`；TRAE `16.8→19.2`；Amie `8.4→10.8`；支小宝 `28.6→31.2`；Google Vids `18→27`。
- 机制：前镜把入口图标/角标/输入框居中放大钻透；后镜从其背后展开完整界面，讲完反向钻回。
- 动势/缓动：Z 推近 `ease-in`，界面展开 `ease-out`。
- 适用：导航进功能页、总览↔详情往返。
- 可程序化：高。

**P3 ★ Pull-Back Reveal Overview（后拉揭示全貌）**
- 频率：高。证据：flowith `82.8→84.6`；Stripe `1.0→5.0`；TME `276→284`；饿了么 `91.8`；MG793 `96→104`。
- 机制：前镜特写一个元素；镜头后拉，四周卡片按层差速展开成全景；自然是"顿悟"的视觉化。
- 动势/缓动：后拉匀速 `ease-in`，前中后景差速。
- 适用：从单结果顿悟整工作流。
- 可程序化：高——多层视差+scale。

**P4 ★ Hero Orbit with Decor Rings（中心环绕装饰环）**
- 频率：高。证据：Riverside `86.4→88.2`；TRAE `123.5→125`；xAI `39.6→43`；三维动画 `12→13`；蚂蚁 `134→140`。
- 机制：中心 hero 不动，镜头缓慢环绕，配同心环/连线，背景连续换景。
- 动势/缓动：绕轴匀速，慢而匀。
- 适用：品牌主角揭幕、合作 logo 群。
- 可程序化：中高——CSS 3D 旋转/GSAP motionPath。

### B. 匹配剪辑三兄弟

**P5 ★ Match Cut by Shape（同形匹配剪辑）**
- 频率：高。证据：阿里 `45.4→49.6`；腾讯 `16.2→25.5`；ColCircle `11.5→15.5`；盒马 `41.6`；a16z `25→34`。
- 机制：前后锁同一形状位置/轮廓，硬切只换物体。自然是形状不变让替换无感。
- 动势/缓动：无运动或同形静帧，切点可加同色遮罩。
- 适用：数字 hold、同构道具换产品。
- 可程序化：高——对齐变换+crossfade。

**P6 ★ Match Cut by Motion（动势方向匹配）**
- 频率：高。证据：盒马 `23.4→26`；ColCircle `63→68.4`；Microsoft 365 `23.4→26`；蜜雪 `14.3→16`；瑞幸 `21→34`。
- 机制：前主体运动出画一侧，后主体沿同侧同速入画。
- 动势/缓动：同方向同速度，切点带运动模糊。
- 适用：角色/物体蒙太奇。
- 可程序化：高。

**P7 ★ Match Cut by Color Veil（整屏色幕藏切）**
- 频率：高。证据：Stripe `7.9→9.0`；creatoroly `6.5`；注意力抓取 `8→9 / 22→24`；Bard `6`；蚂蚁 `96`。
- 机制：品牌色铺满做章节幕，前景留同色元素做桥。
- 动势/缓动：整屏 crossfade，慢而匀。
- 适用：品牌色章节切换。
- 可程序化：高。

### C. 光与流体藏切

**P8 ★ Glow Bloom to Scene（发光体化开新场景）**
- 频率：极高。证据：panel2 `0.0→2.28`；Blink `0.0→3.9`；Win365 `13.0→15.6`；快手 `17.0→19.7`；xAI `14.4→25.2`。
- 机制：前镜发光体过曝膨胀满屏，切点后同一光退成后镜环境光。与现有 hidden-cut 的差别：光本身就是后镜光源。
- 动势/缓动：膨胀 `ease-in` 过曝，退光 `ease-out`。
- 适用：深色电影感开场、章节爆点。
- 可程序化：高——径向渐变+模糊+透明度。

**P9 ★ Liquid Gradient Section Divider（流体光晕章节分隔）**
- 频率：中高。证据：panel1 `7→10`；Stitch `38.77→41.4`；Win365 `13.0→15.6`；NotReal `121.0→122.0`。
- 机制：有机流体涌满→停一拍→散开露新节。与 P8 点光不同，这是整体流体。
- 动势/缓动：湍流慢、膨胀慢。
- 适用：Premium AI 片段落呼吸。
- 可程序化：中高——blob/filter。

**P10 漏光/色散藏切（light-leak / speed-ramp-blur）**
- 频率：中（AGIC 主导）。证据：AGIC `18/37/45`；注意力抓取 `15`；Vivo `28→30`。
- 机制：彩色漏光带或高速运动模糊连续藏切。与现有 hidden-cut / speed-ramp-freeze 高度重合，不单立卡，仅作观察项。
- 可程序化：中。

### D. 共享元素与连续形变

**P11 ★ Shared-Element Morph Chain（共享元素连续形变跨镜）**
- 频率：高。证据：Zelios `11.7→14.3`；支小宝 `18.5→21.5`；Dia `2.0→6.5`；Google AI `32.4→34.2`；Microsoft 365 `12.5→19.5`。
- 机制：同一物体跨多镜连续形变，位置不动。与现有 morph-from-primitive 的差别：跨镜链条而非单次生长。
- 动势/缓动：每步 `ease-out`/弹簧。
- 适用：输入→响应→结果因果链、全片母题。
- 可程序化：高——layout.shared-element+弹簧。

**P12 ★ Device-Frame Content Swap（设备框内换内容）**
- 频率：极高。证据：Wayframe `19.5→23.4`；Win365 `52.0→57.2`；Stripe `6.3→9.4`；荣耀 `9→18`；Conduit `11.7`。
- 机制：外框/样机不动，框内像素或框后环境替换。
- 动势/缓动：框内 crossfade。
- 适用：多端并列、AI 改前改后。
- 可程序化：高。

**P13 ★ Persistent Cursor Across Shots（光标跨镜主角）**
- 频率：高。证据：panel4 全程；Wayframe `5→23`；Similarweb `15.6→24.7`；Gemini `20.8→40.3`；注意力抓取 `11→14`。
- 机制：恒定外观光标跨镜打字/点/拖，操作即转场。与现有 input-trigger-moves 的差别：跨镜连续当主角。
- 动势/缓动：移动 `ease-out`，操作加放大反馈。
- 适用：无真人 Demo、一镜到底工作流。
- 可程序化：高——cursor-follower。

### E. 集合与结构节拍

**P14 ★ Clone Multiply to Grid（单元素克隆成墙）**
- 频率：高。证据：MXD `10.8→12.6`；快手 `39.6/54`；腾讯 `45→50`；CDX `132→138`。
- 机制：单元素复制成 N×M 网格再缩回，表数量感。与 deck-deal/card-stack 差别：一个→增殖。
- 动势/缓动：stagger `ease-out`。
- 适用：素材库/多端矩阵。
- 可程序化：高。

**P15 ★ Split-Screen Split & Merge（分屏合分）**
- 频率：中高。证据：荣耀 `52→57`；Conduit `5.2→11.7`；Riverside `28→31`；蚂蚁 `10`。
- 机制：单画面裂左右→讲→合回。与 before-after-slider 差别：真分屏叙事而非单屏滑杆。
- 动势/缓动：中线滑入/收回。
- 适用：任务 vs 结果、输入 vs 输出。
- 可程序化：高。

### F. 文字与品牌

**P16 ★ Word-Slot Scramble Swap（文字槽乱码换词）**
- 频率：中高。证据：panel1 `5.5→6.5`；deCode `7→10`；Bard `7.8→9.1`；Framer `36→38`；Similarweb `0→1.3`。
- 机制：固定字槽旧词乱码抖动→逐位解码新词，关键词跳色。
- 动势/缓动：逐位解码均匀。
- 适用：排比卖点、章节套版。
- 可程序化：高——text.scramble。

**P17 ★ Particles Gather to Logo（粒子聚合品牌字标）**
- 频率：极高。证据：Framer `63→68`；AGIC `104→106`；蚂蚁 `64→68`；ColCircle `46.8→50.4`；Vivo `84→86`。
- 机制：散点漂浮→向心聚拢→咬合 logo/人形。与现有 brand-ink-open 差别：向内聚合而非向外扩散。
- 动势/缓动：聚拢弹簧回弹。
- 适用：落版、奖项仪式、涌现时刻。
- 可程序化：中高。

**P18 字卡套版换词（kinetic-type-respell）**
- 频率：中。证据：Similarweb `0→9`；ISUX `0→5.4`；TME `5→7`；panel2 `2.28→4`。与 P16 同族，版式套版换字，不单立卡。
- 可程序化：中。

**P19 首尾共享元素闭环（bookend-shared-element）**
- 频率：中高。证据：Waytoagi 花 logo；TME 绿球↔绿气泡；flowith 虹彩球；ISUX 搜索胶囊。与 P11/P17 部分重合，不单立卡。
- 可程序化：中。

**P20 甩镜横移藏切（whip-pan）**
- 频率：低。证据：TME `9.0→9.6`；注意力抓取 `15`。与现有 transition-hidden-cut（运动模糊藏切）同义，不单立卡。
- 可程序化：中。

## 五、推荐进入 Framework 的 Pattern 与筛选理由

筛选硬标准：① ≥2 个不同视频出现；② 易参数化；③ 能用位移/缩放/旋转/遮罩/模糊/透明度/视差等 DOM-SVG-GSAP 实现；④ 能映射到 6 个叙事配方之一；⑤ 与现有 30 卡无同义重复。

| 推荐优先级 | Pattern（候选卡 id） | 理由 |
|---|---|---|
| ★★★ | `transition.zoom-through-portal` | 证据最厚（8+）、电影感最强、直接对应 phone-focus-return、纯 scale+遮罩可实现 |
| ★★★ | `transition.match-cut-shape` | showreel 通用粘接剂，对齐变换即可实现，补 circle-iris 的通用化 |
| ★★★ | `transition.glow-bloom-to-scene` | 深色片高频，径向渐变+模糊，补 hidden-cut 的"光成后镜光源"增量 |
| ★★★ | `ui-entrance.device-frame-content-swap` | AI 产品片刚需，样机不动换内容，纯 crossfade |
| ★★☆ | `transition.shared-element-morph-chain` | 因果链可视化，补 morph-from-primitive 的跨镜链条增量 |
| ★★☆ | `interaction.persistent-cursor-cross-shot` | 无真人 Demo 一镜到底，补 input-trigger-moves 的跨镜连续 |
| ★★☆ | `transition.match-cut-motion` | 角色/物体蒙太奇缝法，运动模糊即可 |
| ★★☆ | `transition.match-cut-color-veil` | 品牌色章节幕，showreel 分组主力 |
| ★★☆ | `opening.particles-gather-to-logo` | 落版/奖项仪式，与 brand-ink-open 方向互补 |
| ★★☆ | `camera.hero-orbit-decor-rings` | 中心 hero 仪式化，3D 旋转可实现 |
| ★★☆ | `transition.ui-drill-in-out` | 总览↔详情往返，对应 phone-focus-return |
| ★☆☆ | `ui-entrance.clone-multiply-to-grid` | 数量感表达，stagger 即可 |
| ★☆☆ | `camera.pull-back-reveal-overview` | 顿悟全貌，多层视差 |
| ★☆☆ | `transition.liquid-gradient-section-divider` | Premium AI 片章节呼吸 |
| ★☆☆ | `typography.word-slot-scramble-swap` | 排比卖点不硬切，text.scramble 现成 |
| ★☆☆ | `transition.split-screen-split-merge` | 任务 vs 结果叙事结构 |

**不推荐立卡（证据薄或同义重复）**：whip-pan（≈hidden-cut）、toast-stack（组件级）、odometer（已有卡）、shape-morph-from-primitive（已有卡）、各类单视频强概念（blade-fold / card-tunnel / hub-spoke 等，待更多跨片验证）。

## 六、Framework 组织建议

现有 8 个 category 不必新增，建议在其下把"镜头级衔接"按职能重新组织为 6 个组，并把现有/新增卡映射进去：

| 新分组（建议命名） | 归属 category | 现有卡 | 本次新增候选卡 |
|---|---|---|---|
| **Camera Movement 镜头运动** | camera | crash-zoom-punch / depth-layer-moves / space-camera-moves / overhead-camera-moves | hero-orbit-decor-rings、pull-back-reveal-overview |
| **Transition 镜头间衔接** | transition | shot-transitions / hidden-cut / wipe / card-flip / circle-iris / line-carry | zoom-through-portal、match-cut-shape、match-cut-motion、match-cut-color-veil、glow-bloom-to-scene、shared-element-morph-chain、liquid-gradient-section-divider、ui-drill-in-out、split-screen-split-merge |
| **UI Transform UI 入场与状态** | ui-entrance | platform-hinge-rise / deck-deal-flyin / card-stack / product-card-progressive-assemble / list-reveal / morph-from-primitive | device-frame-content-swap、clone-multiply-to-grid |

## 七、三个实验设计

### 实验 1：复刻经典转场（Zoom-Through Portal）
- **目标**：用 DOM/SVG/GSAP 把 Win365 `0.0→5.2` 的"书桌→显示器→回书桌"穿框往返复刻成可参数化组件。
- **输入**：两张起始/结束画面（书桌 SVG、浏览器 UI SVG）、一个开口形状（圆形舷窗）。
- **工具**：GSAP（scale + 径向模糊 filter）、SVG `<mask>`、CSS `transform-origin`。
- **输出**：一个 `<ZoomThroughPortal from to hole easing durationMs>` 可复用转场；`previewKind=zoom-through-portal` 的确定性 SVG 演示。
- **成功标准**：① 穿口帧前后中心对齐同一根轴；② 穿口 0.3s 内径向模糊藏切不可见真实切点；③ ease-in-out，往返对称；④ 在 1280×720 与 720×1280 两种比例下不穿帮。

### 实验 2：组合多 Pattern 做 Feature Demo
- **目标**：为一个 AI 写作工具拼一段 15s Feature Demo，按"开场→输入→结果→落版"串 4 个新 Pattern。
- **输入**：产品一个核心功能（对话改稿）、3 张功能截图、品牌色。
- **工具**：GSAP timeline + 候选卡库；串 `persistent-cursor-cross-shot`（光标操作）→ `shared-element-morph-chain`（输入框→结果卡）→ `split-screen-split-merge`（原稿 vs 改后）→ `particles-gather-to-logo`（落版）。
- **输出**：一条 15s 自动编排的演示视频/动画；时间轴标注每段用了哪张卡。
- **成功标准**：① 全程无硬切感、每段衔接可归因到一张卡；② 总时长落在 13–17s；③ 在白/深两套品牌色下都成立；④ 衔接处不出现 UI 跳变或文字抖动。

### 实验 3：Agent 按 Storyboard 自动选 Pattern
- **目标**：给定一段文字 Storyboard（镜头表），Agent 自动为每个镜头间连接选一张最合适的候选卡并填参。
- **输入**：Storyboard 表（每镜：画面内容 / 时长 / 前后关系类型，如"总览→详情""任务→结果""章节切换"）。
- **工具**：候选卡 JSON（`candidate-cards.json`，含 patternIds/narrativeUse/effectIds）+ 一个规则路由（按前后镜关系 → 映射 combo → 选卡 → 取默认 duration/easing）。
- **输出**：带卡 id 与参数的分镜 JSON，可直接喂给渲染器。
- **成功标准**：① 路由命中率 ≥80%（Storyboard 每段都能落到一张卡）；② 选出的卡 patternIds 与该段 combo 一致；③ 不出现"与现有 30 卡同义重复"的误选；④ 生成的时间轴总时长与 Storyboard 偏差 <10%。
