## 文字展示 `text`

**标题 / 金句 / 数据 / 字幕 / Logo 文字**

- **目标**：让观众在最短时间内读懂这句话，并感觉到它重要。
- **一句建议**：先定粒度（按行 / 按词 / 按字符），再定顺序。一个镜头只留一个主动作，正文尽快稳定下来。
- **硬约束**：文字必须 100% 正确，且极可能被反复改文案。因此这一场景永远留在确定性层，绝不交给生成模型。
- **典型镜头**：开场主标题 · 章节标题 · 数据结论句 · 金句卡 · Logo 锁定 · 字幕 / 下三分
- **节奏**：一个镜头只允许一个主动作。标题负责表现力，正文尽快稳定下来。
- **时长参考**：单镜头 1.2–3.0 秒；文字动效本体 ≤ 1.2 秒，其余是停留时间。
- **渲染层**：`deterministic` — 可以用 Shader 做背景或光效，但字形与排版必须在 DOM / SVG 里。

### 提示词模板

```text
{触发时机}，主标题使用{动效名称}（{English name}）。{表现细节}。正文字号保持稳定清晰，不要逐字播放；整段动效在 {时长} 内完成，字形与排版不要交给生成模型。
```

可直接取用的本场景首选示例：

- **淡入与淡出（Fade in / Fade out）**：页面内容使用柔和的淡入（Fade in）。标题先出现，正文随后淡入；关闭弹窗时使用更快的淡出（Fade out）。避免整页所有元素同时显现。
- **模糊显现（Blur reveal）**：首屏标题使用模糊显现（Blur reveal），从轻微模糊逐渐变清晰，同时淡入并小幅上移。只用于主标题和重点图片，正文保持稳定清晰。
- **裁剪揭示（Clip-path reveal）**：主视觉图片使用裁剪揭示（Clip-path reveal），从左向右平滑展开。图片本身保持稳定，只改变可见区域；效果干净，不叠加旋转和夸张缩放。

## 背景转场 `bg`

**镜头之间的过渡 / 章节切换 / 氛围背景**

- **目标**：把两个镜头缝在一起而不让观众察觉接缝，或者建立一段氛围。
- **一句建议**：转场是缝合件，不是主角。优先选能保留前后画面清晰度的做法，并把时长压到 0.8 秒内。
- **硬约束**：转场是纯「像素变换」，不需要模型理解世界，绝大多数应该由 Shader 或确定性层完成。
- **典型镜头**：章节间的 Wipe / Dissolve · 镜内视差景深 · 氛围背景循环 · 色幕过渡 · 生成镜头与 HTML 镜头之间的缝合
- **节奏**：转场要快而准。功能型内容里频繁使用长转场会让每次切换都变慢。
- **时长参考**：转场本体 0.3–0.8 秒；氛围背景按镜头时长循环，循环首尾要能无缝相接。
- **渲染层**：`shader` — 生成层只在背景本身是「真实世界重构」（火焰、城市变形、水体）时使用，且一律按不透明 plate 处理。

### 提示词模板

```text
{触发时机}，使用{动效名称}（{English name}）完成两个画面之间的过渡。{表现细节}。转场本体控制在 {时长} 内，为前后镜头各留 {handles} 帧 handles；字体、Logo、数据等元素单独走确定性层合成，不要让转场吃掉它们的清晰度。
```

可直接取用的本场景首选示例：

- **交叉淡化（Crossfade）**：切换标签页时使用交叉淡化（Crossfade）：旧内容淡出的同时，新内容在相同位置淡入。保持容器高度稳定，快速切换时取消上一段未完成动画。
- **蒙版显现（Mask reveal）**：图片使用蒙版显现（Mask reveal），通过柔和渐变蒙版从中央向外显现。边缘保持自然，不要出现生硬矩形；只用于主视觉区域。
- **擦除转场（Wipe transition）**：章节切换时使用擦除转场（Wipe transition）：一个纯色遮罩从左向右扫过，覆盖旧内容后带出新内容。动作清楚、节奏利落，用户快速导航时允许跳过。

## 卡片展示 `card`

**信息卡 / 数据卡 / 作品卡 / UI 卡片**

- **目标**：让观众看懂「有几张、什么关系、我要看哪一张」。
- **一句建议**：一组卡片要像一次动作，不要变成排队等候；卡片里的文字与数字不参与缩放和倾斜。
- **硬约束**：卡片内部通常含真实文字与数字，因此卡片本体、排版、数字全部留在确定性层。
- **典型镜头**：卡片列表入场 · 筛选结果重排 · 卡片展开到详情 · 悬停抬升 · 数据卡片计数
- **节奏**：一组卡片的节奏要连贯，间隔要短到像一次动作，否则会变成排队等候。
- **时长参考**：单卡入场 0.4–0.7 秒，整组（4–6 张）控制在 1.0–1.6 秒；交错间隔 40–80ms。
- **渲染层**：`deterministic` — 卡片上的生成元素只能是背景或装饰图，任何文字层都必须独立可编辑。

### 提示词模板

```text
{触发时机}，{数量}张卡片使用{动效名称}（{English name}）依次进入，按从左到右、从上到下的阅读顺序。{表现细节}。相邻卡片间隔 {交错间隔}，整组像一次连续动作；卡片上的文字与数字保持清晰稳定，不参与缩放或倾斜。
```

可直接取用的本场景首选示例：

- **交错出现（Stagger）**：让六张卡片交错出现（Stagger），按照从左到右、从上到下的阅读顺序依次进入。相邻卡片只保留很短的间隔，整组动画连贯、轻快。
- **淡入与淡出（Fade in / Fade out）**：页面内容使用柔和的淡入（Fade in）。标题先出现，正文随后淡入；关闭弹窗时使用更快的淡出（Fade out）。避免整页所有元素同时显现。
- **滑入与滑出（Slide in / Slide out）**：移动端菜单从右侧滑入（Slide in），关闭时沿原方向滑出（Slide out）；章节标题从下方轻微滑入。保持位移克制，让用户看得出方向即可。

## 手机产品演示 `screen`

**设备展示 / 模拟操作 / 局部放大**

- **目标**：在一个竖屏画框里可信地演示一次移动端操作，或在横版视频里展示手机产品本身。
- **一句建议**：用本地示例界面 + 中性设备框，不依赖实时网站。一次演示只讲一个操作，手指落点要有停顿。
- **硬约束**：触屏没有悬停、没有常驻光标。另外设备内屏比例与最终输出画幅是两件事，必须分开配置：内屏按设备（如 393×852），输出按交付（默认 16:9，也支持 9:16）。
- **典型镜头**：设备入场 · 操作演示 · 屏幕讲解 · 局部放大 · 底部面板 / 抽屉 · 加载到成功的完整链路
- **节奏**：一次演示只讲一个操作。手指落点要有停顿，让观众看清按了哪里。
- **时长参考**：设备入场 4 秒 / 操作演示 6 秒 / 屏幕讲解 6 秒（对应 presets 里的三个镜头预设）。
- **渲染层**：`deterministic` — 屏幕内容以 DOM/SVG 渲染后合成进设备框；外壳与手部可以是生成层，但屏幕区域必须可独立替换。

## 图表数据叙事 `chart`

**对比 / 趋势 / 占比 / 前后 / 归因 / 排名**

- **目标**：让观众在 3–8 秒内看懂一个数据结论，并能停在一个可读、可核对的终态。
- **一句建议**：先立标题、单位与坐标，再让图元增长，最后标注结论。每段演示都要留出明确的阅读停留。
- **硬约束**：数值必须精确且可审计：任何时刻都能给出最终值，图元的长度、面积和计数不做超调插值；缺失值不当作 0；占比要求非负且总和有效，不静默修改数据。
- **典型镜头**：柱状对比 · 折线趋势 · 占比条 · 前后对比 · 瀑布归因 · 排名变化
- **节奏**：建立坐标 → 图元增长 → 强调目标项 → 停留读数。数据标签不得抖动或互相遮挡。
- **时长参考**：4–8 秒；排名变化最长（8 秒），对比与前后最短（4 秒）。
- **渲染层**：`deterministic` — 用 GSAP + SVG 自绘，不引第三方图表库；示例数据可参数化、可校验、可恢复默认。
