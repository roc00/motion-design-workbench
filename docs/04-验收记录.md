## 五、来源偏差与未完成项

### 与 PLAN 的偏差（已按实际情况调整）

1. **第五场景的条目**：PLAN 说「六个图表词条追加编号」。实际按 57–62 追加，原 1–56 编号未动，校验器改为「编号从 1 连续到 N」而不是写死 56。
2. **占比总和不为 100**：PLAN 要求「不静默修改数据」。实现为：校验器给警告、界面按原值展示，**不做归一化**，也不阻止播放（总和为 0 或出现负值才拒绝）。这是有意的分级。
3. **图片序列**：无法获得某一主体的真实连续帧，改用**确定性绘制序列**（24 帧对应 24 个旋转角度，帧号与画面严格对应），并在界面上标注为「设备旋转 · 确定性绘制序列」，不冒充实拍序列帧。
4. **交互原理模式的素材**：真实滚动用宿主 `overflow` + `position: sticky` 实现（真的能滚），指针类用真实 `pointermove`；这两种模式下进度条与播放按钮按能力禁用，不伪装成可定位。

### 未完成项

1. **案例库仍是空的**。61 条条目的 `cases` 全部为空；本轮按要求不推进外部经典案例。
2. **没有真机触屏验证**。响应式是在无头浏览器里用同源 iframe 按 1440×900 / 1024×768 / 768×1024 / 390×844 四档测量 CSS 布局，没有在真实手机上验证触摸手感与惯性滚动。
3. **素材未本地化**。演示图片仍走 `picsum.photos` 网络请求，固定 seed 只保证同一张图，不保证可复现资产；离线时是占位底色。
4. **尚未跑实际 MP4 渲染路径**。已有渲染器无关的帧输入合同、竖屏组合运行时和资源门禁，但尚未接到 Remotion/离屏渲染并输出技术样片，所以没有组件标记为 `production-verified`。
5. **无障碍只做了键盘与焦点**。没有做屏幕阅读器朗读顺序的完整验证，配色的对比度也未逐项测量。
6. **性能未做量化**。卡片预览用 IntersectionObserver 限制在视口附近挂载，但没有测过同时挂载上限与长时间运行的内存曲线。
