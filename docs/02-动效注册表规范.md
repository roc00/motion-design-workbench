# 02 · 动效注册表规范

## 文件分工

数据放在 `data/`，五个文件各管一件事，互不重复：

| 文件 | 管什么 | 层级 |
|---|---|---|
| `data/tools.json` | 实现工具 + 4 个渲染层 + 路由判据 | 第一层 · 技术工具 |
| `data/triggers.json` | 触发方式，各带别名、变体、组合与提示词示例 | 第二层 · 触发方式 |
| `data/effects.json` | 全部条目（效果 / 原理 / 规则）+ 五场景适配度 | 第三层 + 第四层 |
| `data/scenarios.json` | 场景定义、约束、注意事项、提示词模板 | 选型轴 |
| `data/presets.json` | 实际运行值：演示内容、时间安排、代表帧、资产；手机镜头；图表数据 | 预览与输出 |

**单一真相源**：

- 「某条目在某场景能不能用」→ 只写在 `effects.json` 该条目的 `scenarios`。
- 「在某场景使用（或不用）它要注意什么」→ 只写在 `scenarios.json` 该场景的 `notes`。
- 「这条演示具体跑多久、显示什么」→ 只写在 `presets.json`。
- `docs/01-场景选型矩阵.md` 是派生文档，由 `scripts/gen-matrix.mjs` 生成，不要手改。

改完数据必须跑：

```bash
npm run validate      # 结构 + 预设 + 图表数据校验，有错退出非零
npm run docs:matrix   # 重新生成选型矩阵
npm run build         # 先跑绑定闸门，再产出 public/registry.json
```

## 条目字段

```jsonc
{
  "id": "text.line-reveal",        // 全局唯一，格式 组.英文短名
  "no": 15,                        // 编号从 1 连续到 N，不跳号
  "zh": "按行显现",
  "en": "Line reveal",
  "group": "文字动效",
  "layer": "动效类型",              // 动效类型 | UX 规则
  "nature": "effect",              // effect | principle | rule
  "trigger": ["in-view", "load"],  // 触发 id 或别名
  "core": "一句话核心动作。",
  "variants": ["常见类型 A", "常见类型 B"],
  "fits": ["适合用在哪"],
  "avoid": ["禁忌"],
  "scenarios": {                   // 五个场景必须全部出现
    "text": "core", "bg": "avoid", "card": "good", "screen": "good", "chart": "good"
  },
  "niche": true,                   // 可选：适用面很窄
  "nicheNote": "为什么窄",
  "render": "deterministic",       // deterministic | shader | generative | hybrid
  "shotRoles": ["opening-title"],
  "timing": {
    "duration_ms": [500, 900],     // 建议区间（词典的建议范围）
    "easing": "ease-out",
    "stagger_ms": [80, 140],
    "note": "实现上的一条硬约束"
  },
  "prompt": "可以直接交给 AI 的一句话。",
  "video": "落地到动效视频时的注意事项。",
  "demo": "text",                  // 演示引擎（src/engine/<demo>.js）
  "demoVariant": "line-reveal",     // 引擎内的变体名
  "cases": []
}
```

**`demo` + `demoVariant` 是代码绑定**，必须与 `src/engine/<demo>.js` 的 `variants` 键一致。`npm run build` 会检查，不一致直接失败。

### nature 取值

| 值 | 含义 | 界面行为 |
|---|---|---|
| `effect` | 具体动效 | 参与本场景的首选 / 可用 / 慎用排序 |
| `principle` | 参数取值方式（缓动 / 时长 / 延迟） | 单列「原理与规则」，保留演示 |
| `rule` | UX 约束（五条） | 同上 |

### 场景适配度

`core` 首选 / `good` 可用 / `caution` 慎用 / `avoid` 不用。

判据：适配度说**能不能用**，场景的 `notes` 说**用的时候要小心什么**。

## 预设字段

```jsonc
"text.line-reveal": {
  "still": 0.55,                   // 代表帧位置 0..1（卡片与静态态用它）
  "content": {                     // 演示真正显示的内容，可被界面编辑
    "lines": ["把动效", "讲清楚", "才能做对"],
    "seed": "facade"
  },
  "timeline": {                    // 时间安排（ms），是制作指令与镜头配置的来源
    "actionMs": 520,
    "staggerMs": 120,
    "holdMs": 500,
    "exitMs": 0
  }
}
```

- `still`：图表与结果类取 `0.95`（终态可读），其余取 `0.55`（动作中段可辨识）。
- `timeline` 的四个字段会换算成帧数写进镜头配置；**handles 单列**，不计入可见时长。
- `content` 里的 `seed` 是 Picsum 的固定种子，属于「资产引用」，不是可复现资产本身。

## 叙事配方

`compositions.json` 记录可复用的表达组织方法。它与内容场景分开：内容场景回答「承载什么」，叙事配方回答「观众要理解什么、镜头怎样接」。

每个配方必须包含 `purposeId`、`goal`、`audienceTakeaway`、`contentTypes`、`formats`、`conditions`、`attention`、`beats`、`continuity`、`evidence`、`failureExample`、三个 `keyframes` 和可执行的 `tracks`。项目内容不得写进通用条件或选择规则。

校验器会检查筛选维度、能力状态、三个关键帧、动作节拍和阅读停留。工作台生成的中文制作指令与组合 JSON 必须消费同一条配方，缺失语义时直接报错，不自动编造。

## 手机镜头预设

`presets.json` 的 `shots` 是三个组合预设（设备入场 4s / 操作演示 6s / 屏幕讲解 6s），每个含 `steps`（时间点 + 动作 + 引用的效果 id）、`device`（内屏尺寸）与 `output`（输出画幅与帧率）。校验会检查步骤时间严格递增、不超出总时长、引用的效果存在。

---

## 图表数据

`presets.json` 的 `charts` 保存六组示例数据。规则写在 `src/chart-rules.js`，**Node 校验脚本与浏览器演示共用同一份规则**，不会出现「校验说没问题、界面画错」的情况。规则要点：

- 柱状对比：值必须是有限数字；高亮项必须存在于数据里。
- 折线趋势：`labels` 与 `values` 等长；允许 `null` 表示缺失（折线断开，不补零）；至少要有一个非缺失值。
- 占比：不允许负值；总和不为 100 时**不静默归一化**，界面按原值展示并给出警告。
- 瀑布：起点 + 各项增减必须等于终点，否则拒绝播放。
- 排名变化：实体颜色唯一（靠颜色识别实体）；每一帧必须覆盖同一批实体（否则会制造不存在的排名变化）。
- 数据校验不通过时**不启动播放**，界面直接显示错误面板，不静默修改数据。

## 补充案例

案例写在**对应条目**的 `cases` 数组里，不要另建文件。字段：

```jsonc
{
  "title": "案例名（能搜到的产品名 / 作品名）",
  "source": "https://...",            // 来源链接
  "preview": "截图或录屏路径",          // 可选
  "scenario": "text",                 // 这个案例属于哪个场景
  "effectId": "text.line-reveal",     // 它演示的是哪个动效
  "why": "为什么值得收录 —— 一句话说明它做对了什么",
  "borrow": "可以借用到自己项目里的哪一部分",
  "params": { "duration_ms": 720 },   // 可选：观察到的参数
  "addedAt": "2026-09-18"
}
```

界面会呈现来源、预览、所属场景、值得借鉴之处与观察参数；没有案例时给简洁空态。**未实际收集的案例不能拿演示素材冒充**。

## 新增一个条目

1. 在 `effects.json` 追加，`no` 接在当前最大号之后。
2. 补 `nature`、五个场景的适配度、`prompt`（必须是一句能直接交给 AI 的话）、`render`、`timing`、`video`。
3. 在 `presets.json` 的 `demos` 里加同 id 的预设。
4. `demo` 选一个现有引擎；若是全新形态，在 `src/engine/` 加一个引擎文件，导出 `variants`。
5. 跑 `npm run validate && npm run docs:matrix && npm run build`。

## 校验覆盖范围

`npm run validate` 检查 12 项，任一失败退出非零码：

1. id 唯一；编号从 1 连续
2. `nature` 合法
3. 每条完整覆盖场景注册表里的全部场景，取值合法
4. 场景键只能是注册表里声明过的 id
5. `trigger` 能解析到触发表的 id 或别名
6. 场景 `notes` 引用的条目存在
7. 每个场景至少 6 个 `core`/`good`
8. 每个 `effect` 至少在某个场景是 `core` 或 `good`（除非标了 `niche`）
9. `render` 落在渲染层注册表里
10. 每个条目都有预设、没有多余预设；`timeline` 字段合法且总时长为正
11. 手机镜头预设：步骤时间严格递增、不超总时长、引用有效、内屏尺寸存在
12. 图表数据：六类各自的业务规则

`npm run build` 额外检查：`demo` + `demoVariant` 必须能在 `src/engine/` 解析到。
