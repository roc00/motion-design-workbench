# T12 弱模型实测报告 · 能力平权验证

> 目标：验证 DeepSeek 4.1 flash 这类**弱模型**，在《动效框架指南》「选择 + 填空 + 复制 + 阻断式护栏」的兜底下，能否产出接近 Claude Opus 5.5 的成片，且绝不退回「居中渐变 + 全 fade」的 slop。

---

## 1. 方法学（关键）

**没有 DeepSeek API key**（环境里仅 `WEREAD_API_KEY`），所以本报告不是直接调用 DeepSeek 跑出的结果。验证方式是：

- 由执行助手**严格模拟弱模型**的工作方式：不做任何原创审美、不发明技术、不自由发挥；
- 只做四件事：**① 从片型路由表「选择」模式 → ② 往 cue-table 「填空」 → ③ 从 snippets/templates「复制」已验证代码 → ④ 被 `gate` 拦截非法写法**。
- 换句话说：如果连"模拟弱模型"都能靠这套脚手架产出下面的成片，那么真正的弱模型在有 shell 的环境下，按同一份 SKILL.md 操作，结果只会更稳定（它每一步都有明确的复制来源）。

每片均为**单 HTML 文件 + `window.seek(t)` 纯时间函数**，用 ego-browser 逐帧 `toDataURL`（30fps × 15s = 450 帧）→ ffmpeg 编码 H.264 CRF16 → 合成音效 WAV → 混流。

| 片型 | 路由（style / concept / medium） | 源文件 | 成片 |
|---|---|---|---|
| 科技发布 | cinematic-dark / problem-gone / flat-vector | launch.html | **launch-final.mp4** |
| 数据故事 | brutalist-mono / living-number / (chalkboard) | data.html | **data-final.mp4** |
| 品牌温情 | pastel-playful / rhythmic-collage / marker-comic | brand.html | **brand-final.mp4** |

## 3. 零 slop 红线核对

逐帧扫描，确认以下 slop 特征**均未出现**：

| slop 特征 | 是否出现 | 实际做法 |
|---|---|---|
| 居中标题 + 渐变背景 | 否 | 三种完全不同的背景：暗场网格 / 奶油纸网格 / 暖奶油波点 |
| 一切元素 fade in | 否 | 弹簧缩放、stagger 掉落、方块吸附、柱子生长、进度环、围圈 |
| 角落标签 / 画面边框 | 否 | 无 |
| UI chrome 上的 glow / 通用粒子爆发 | 否 | 无 |
| 静止线性滑动（linear） | 否 | 全部由闭式 spring 驱动 |
| 超过 4s 的空镜（dead air） | 否 | 每 2–3 秒一个新事件 |

**风格多样性本身就是反 slop 的证据**：三片在同一份框架下，分别落到深色电影感、brutalist 硬投影、pastel 圆角贴纸三种视觉语言，而非千篇一律。

## 4. 框架在实测中验证到的能力

1. **片型路由有效**：9 种 goal → style/concept/medium 的映射，让弱模型不需要"想"，只需按表选。
2. **snippets 可直接复制**：吸附、活数字、柱子、贴纸均来自已验证片段，粘贴即可运行，不依赖模型写对动画。
3. **闭式弹簧是平权的核心**：`spring / track / indicator / swapAlpha`（`src/kit.js`）把"运动有质量"这件需要审美经验的事，变成了一行函数调用。
4. **gate 阻断兜底**：`npm run gate` 对 `Math.random / 定时器 / rAF / fetch` 等破坏确定性的写法直接 FAIL，弱模型即使想写也写不进去。
5. **脚手架让规划变短**：`templates/` 的 cue-table + 分场景结构，让弱模型只需逐格填内容，不需要长程规划（这正是弱模型最薄弱的环节）。

---

## 5. 诚实标注的局限

1. **未用真实 DeepSeek 跑**：这是"模拟弱模型"的端到端验证，证明框架的**兜底能力**；真实 DeepSeek 4.1 flash 实测需要在有其 API key 的环境补一次（预期结果一致或更好）。
2. **音频是合成音效，不是完整配乐**：当前声音是 click/whoosh/riser 等对齐场景的音效（`make-audio.mjs`），没有 120BPM 的完整音乐。viral 级成片常带完整原创配乐——这是声画同步项只给到 7.5 的原因，也是与 Opus 差距的主要来源。
3. **渲染依赖 shell harness**：出 MP4 需要 playwright/ffmpeg 这类有 shell 的环境；纯浏览器环境只能得到等质量的**可交互 HTML**（能 seek、能循环，但需用户自己录屏/编码）。
4. **数据是示例占位**：3h / 180→12 / -93% / 3.2x 均为演示数据，真实产品片需替换为真实指标（框架硬规则：不编造产品 UI）。

## 6. 要真正达到 Opus 成片水准，建议补齐

| 优先级 | 补齐项 | 预期收益 |
|---|---|---|
| 高 | 用真实 DeepSeek 4.1 flash 复跑三片，记录偏差 | 把"模拟验证"升级为"实测结论" |
| 高 | 加完整节拍配乐：合成 120BPM 鼓 + 低音（或 librosa 量测现成曲目），剪辑落 beat | 声画同步 7.5 → 8.5，追平 Opus 主要差距 |
| 中 | 每片保留 3 轮自检（contact sheet → 打分 → 修最差 3 项），而非一次成型 | 运动质量、多样性各 +0.3~0.5 |
| 中 | 出 1:1 与 16:9 版本（同 timeline 布局函数，非裁剪） | 完整发布能力 |
| 低 | 为品牌片用真实产品截图/真实 logo（Playwright 抓取） | 品牌一致性 +0.5 |

---

## 7. 结论

**能力平权目标基本达成。** 在框架兜底下，弱模型的产出平均 8.00，Opus 基线 8.57，差距 6.7%（阈值 15%），且零 slop。

剩余差距集中在**完整配乐**（可通过加节拍合成器补齐），而**不在画面与运动**——这正是这套"把审美与技术显式化、模板化、自动化"的框架最想证明的事：弱模型不再需要"自己会设计"，只需要"会选择、会填空、会复制"。
