# Google 是怎么用 60 秒讲好一个新功能的？（Gemini Canvas，BA品牌引力）

## 基础信息
- 类型：产品宣传 / UI Demo（Google Gemini Canvas）
- 风格：深色 + 紫蓝辉光，极简 UI，大量负空间，手型光标贯穿
- 适用场景：AI 写作/编程/文档类产品的功能发布片，「光标带操作」+「文字打散重组」手法可直接借鉴。
- 时长 / 大致镜头数：60s，cuts 仅 1 个硬切，实为一镜到底 UI 漫游；估算 12–15 个状态。

## 镜头结构
- 开场（0–5.2s）：Gemini 星标 →「Hello, Teresa」多屏 →「Your AI assistant from Google」。
- 章节字卡（5.2–13s）：「Reimagined for better」打散成字符，飞散重组为「collaboration」，再到「Introducing Canvas in Gemini」。
- 功能漫游（13–50.7s）：输入 prompt → 初稿文档 → 光标拖「Change length」滑块 → 点建议卡 → 「I want to build an app」→ 代码 → Code/Preview 切换 → 落地 docs/timelines/data/games/apps 多种 Canvas 产物。
- 收尾（50.7–60s）：「All in one space」胶囊 →「Canvas」胶囊 →「Hello, Teresa」屏 → CTA「Try Canvas in Gemini today」。
- 节奏：长镜无缝，UI 状态间靠光标移动与文字淡入连接。

## 动势（挑最典型）
- **syllable-scatter-reassemble（6.5–9.1s）**
  - Movement：整句字先向四周炸开，再向新位置汇聚。
  - Timing：Fast Out / Slow In。
  - Easing：炸开 ease-out，汇聚 ease-in-out（带轻微 spring）。
  - Feeling：Premium / Playful。
- **cursor-carry（20.8–28.6s）**
  - Movement：光标在 UI 平面上移动、拖、点。
  - Timing：Slow Reveal（让观众读操作）。
  - Easing：ease-out（光标落点轻微弹性）。
  - Feeling：Technical。

## 空间与布局
- 全程深色 UI 平面，镜头不离开界面，靠光标位置与 UI 块的淡入淡出组织叙事；文字段在纯黑中用散字重组做章节，UI 段用「顶部小标题 + 中央产物」的固定版式轮替，空间始终扁平，靠光标高亮引导阅读顺序。

## 可沉淀的 Pattern 候选
1. **syllable-scatter-reassemble（字符旅行重组）**：一句文案散成单音节字符在负空间飘飞，再飞到新位置拼成另一个词。证据 6.5–9.1s。解决「两个章节词之间的字卡过渡」，比硬切字卡更有动感。
2. **cursor-carry-as-transition（光标即转场）**：手型光标拖滑块、点卡片、切开关，每次真实操作都把当前 UI 带入下一个状态。证据 20.8–23.4s、24.7–28.6s、37.7–40.3s。解决「产品演示片如何让转场=交互」，把操作演成叙事。
3. **ui-journey-continuous（一镜 UI 漫游）**：prompt→文档→代码→预览→具体产物，全程不切镜头，只靠文字与 UI 块淡入淡出和光标移动串联。证据 13–50.7s。解决「单功能多步骤演示」不碎。
4. **crash-zoom-word-to-new（急推单词出章节）**：对一个词急推模糊，糊掉后淡入下一个章节词。证据 9.1–11.0s。解决「字卡之间的强调切」。
5. **pill-to-screen-loop（胶囊拉回开场屏）**：结尾把胶囊拉成开场那句「Hello, Teresa」再出 CTA。证据 52–55.9s。解决「首尾闭环收尾」。
